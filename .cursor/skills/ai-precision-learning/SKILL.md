# AI 精准学习（闭环）

## Obsidian 知识库联动（强制）

> 目标：在学习流程中“先问本地知识库，再补充外部资料”，并把问答记录回写到 Obsidian，形成可追溯学习轨迹。

### 固定路径（当前用户环境）

- **主 Vault（本机）**：`D:/Obsidian/repository/Obsidian Vault`
- 索引：`D:/Obsidian/repository/Obsidian Vault/llm-wiki/index.md`
- 日志：`D:/Obsidian/repository/Obsidian Vault/llm-wiki/log.md`
- 问答：`D:/Obsidian/repository/Obsidian Vault/llm-wiki/qa-records.md`
- **仓库内回退知识库（Portable）**：与本仓库同级的 `obsidian-vault/LLM_Learning/wiki/`（及 `raw/` 原文档）。当主 Vault 路径不可读或检索无命中时，**必须**在此目录内 `rg`/搜索相关 `.md` 作为第一依据；命中路径使用**相对仓库根**书写，便于协作与 CI。

> 子工程可在 `learning/<项目>/obsidian_bridge.md` 中声明「主 Vault 是否覆盖为其它路径」。

### 提问处理顺序（必做）

1. **先检索 Obsidian 本地知识库**  
   优先在 `Vault 根目录` 下检索相关 Markdown（`*.md`），从命中内容中提炼答案主干；禁止先给结论再倒推来源。
2. **本地证据不足时再补 MCP / Web**  
   若本地资料不足以回答完整问题，再补充权威外链；回答中要区分「本地知识库依据」与「外部补充依据」。
3. **回答必须带来源分层**  
   至少包含：`本地知识库命中文件`（路径）与（如有）`外部 URL`。
4. **每次问答后回写 Obsidian**  
   - 在 `llm-wiki/qa-records.md` 追加完整问答记录；  
   - 同步在 `llm-wiki/log.md` 追加一条摘要索引。  
   记录模板：

```markdown
## [HH:mm:ss] Q: <用户问题>
- Context: <当前学习项目/知识块>
- Hits:
  - <命中文件路径1>
  - <命中文件路径2>
- Answer-Summary: <3~6 行摘要>
- References:
  - <Vault 文件路径或标题>
  - <外部 URL（如有）>
```

## 核心理念

先搭框架 → 再练反馈 → 最后输出验证；全程用**可复制的精准指令**驱动。  
一句话：**不是瞎学，是用 AI 精准学、高效学、闭环学。**

## 何时应用本 Skill

用户明确要按本流程学习，或使用下方**触发语**时，按顺序执行「学习流程」与「子工程创建」（若适用）。

## 触发语（用户复制即用）

### A. 快速模式（信息已想清楚时）

```text
/精学流程 我想掌握【领域或技能名称】；当前水平与可用时间：（简述）。请按 ai-precision-learning：先画学习地图，再约定本仓库子工程目录名，并从 skills/_template 创建对应子项目。
```

### B. 分步模式（推荐：初始化子项目前**一步一步追问**）

**用下面整段开启「流式访谈」**：每次回复只问**一个问题**，等用户回答后再问下一个；**禁止**一次抛出整张问卷或长列表。

```text
/精学分步 请按 ai-precision-learning 用「分步访谈模式」带我：先弄清我想学什么、当前水平、想学到什么程度，再画学习地图并初始化 skills/ 子项目。全程一次只问我一个问题，我答完再问下一题。
```

说明：

- `/精学流程`：适合已能一次性说清楚领域、水平、时间的情况。
- `/精学分步`：适合希望像向导一样**渐进澄清**再建子工程的情况。
- 若用户只发 `/精学流程` 或 `/精学分步` 且无补充说明：分步模式**只发欢迎语 + 第一个问题**；快速模式可照旧简短追问三项后进入地图。

## 分步访谈模式（子项目初始化前必守）

当用户使用 **B. 分步模式**触发语，或明确说「一步一步问」「一次一个问题」时：

1. **交互规则**
   - 每条助手回复：**最多一个明确问题**（可加一句为什么要问），**不要**在同一轮里问多题。
   - 用户回答后，简短确认理解（可 1 句话），再进入下一题。
   - 信息够用时，用一小段**复述用户画像**（领域、基础、目标深度、时间）请用户确认「是否准确」，确认后再进入「学习地图」与「子工程创建」。

2. **建议提问顺序**（按序一次一项；可跳过已答项）
   - 想掌握的**领域 / 技能**具体是什么？（例：Python 基础、Prompt、LangChain）
   - **当前水平**自评：零基础 / 用过一点 / 能写小项目 / 其他？有无相关经历可举 1 例？
   - **目标深度**：偏「能上手用」、「能面试/考证」、还是「能独立做项目」？有无截止或里程碑？
   - **每周可投入时间**与偏好节奏（每天一点 / 周末集中）？
   - 是否已有**子工程文件夹名**想法？若无，助手给 2～3 个 **kebab-case** 候选让用户选一个。

3. **复述确认通过后**才执行文件操作  
   再执行下方「代理执行顺序」中的学习地图与子工程创建；创建完成后提示用户本地 `venv` 与 `pip install -e ".[dev]"` 命令（见仓库根 `README.md`）。

## 代理执行顺序（触发后必做）

**注意**：在分步模式下，须完成「分步访谈模式」第 2～3 步（信息收齐 + 用户确认复述）后，才执行下面第 1～2 步。

1. **知识库检索（Obsidian 优先）**  
   对当前主题先在可读的主 Vault（`D:/Obsidian/repository/Obsidian Vault`）与 **仓库内回退**（`obsidian-vault/LLM_Learning/wiki/`、`raw/`）检索并读取相关 `.md`，提炼学习地图与讲解主干；若命中不足再补 MCP。

2. **学习地图（框架）**  
   用「精准指令 1」的逻辑输出：核心知识点（抓约 20% 覆盖约 80%）、学习路径、分阶段目标与每阶段可验收产出。  
   语言：与用户一致（默认中文）。

3. **子工程（本仓库）**  
   若尚未指定目录名：根据领域与用户协商一个 **kebab-case** 文件夹名，例如 `python-basics`、`langchain-apps`。  
   子工程**默认**放在 `skills/<目录名>/`；若用户希望「**学习项目** + 实战区 + 可编辑子工程」，可改为 `learning/<学习项目名>/<目录名>/`，**实战 demo** 放在仓库根与 `learning/` 同级的 `practical/`（见仓库根 `README.md`）。  
   然后在本仓库执行（路径以实际落点替换 `…`）：
   - 将 `skills/_template` **复制**为 `…/<目录名>/`（若已存在则不要覆盖，改为追问是否用新名字或合并）。
   - 更新 `…/<目录名>/pyproject.toml` 的 `name`、`description`。
   - 将 `src/skill_template` **重命名**为与包名一致的 Python 包目录（如 `python_basics`），并修正 `tests/` 中的 `import`、必要时修正 `pyproject.toml` 里 `[tool.setuptools.packages.find]`。
   - 在 `…/<目录名>/README.md` 顶部写入：学习地图摘要、阶段目标、与本阶段验收标准；若使用 `learning/`，在 README 中说明仓库根 `practical/` 的用途与相对路径。
   - 在子工程根新增 `obsidian_bridge.md`：记录 Vault 根路径、问答日志路径、知识库命中记录约定（用于和 Obsidian 双向同步学习轨迹）。

4. **后续节奏**  
   提醒用户可在同一会话中继续用「精准指令 2–4」；进入「验证」阶段时用「输出验证」小节。

## 四条精准指令（教用户这样发话）

用户可直接复制括号并替换：

### 1. 让 AI 画学习地图

```text
我要快速掌握【领域】，给我核心知识点、学习路径、阶段性目标。
```

### 2. 让 AI 做通俗讲解

```text
要讲解：用最简单的比喻，零基础解释【知识点或知识块名称】。
```

（亦可简写为「要讲解：【XXX】」；代理按下方「要讲解（notebooks 专题包）」协议落盘。）

### 3. 让 AI 当私教刷题

```text
我练习【技能】，出 5 道题，我答完后帮我纠错并讲解。
```

### 4. 让 AI 做费曼检验

```text
你当小白，我讲【内容】，你一直提问，直到我讲明白。
```

## 要讲解（notebooks 专题包）

当用户发送**「要讲解：用最简单的比喻，零基础解释【知识块】。」**（或等价触发：明确「要讲解」+ 知识块名）时，代理须按下列协议为当前学习子工程生成材料；**默认根目录**：`learning/<学习项目名>/<子工程名>/notebooks/`（例：`learning/python-advanced-learning/python进阶/notebooks/`）。

### 生成前（必做）

1. **读取笔记模板**：生成任意 `{子知识点}_note.md` 前，必须先打开并遵循**笔记模板**的章节结构与排版（标题层级、分块方式、`参考资料` 区块位置等），在该骨架上撰写正文，禁止凭空换一种完全不同的笔记版式。模板优先级：  
   - **默认**：仓库根下 `learning/Demo.md`；  
   - **覆盖**：若当前学习子工程 `notebooks/` 下存在 `template.md`、`_note.template.md`（或用户在对话中指定的其它模板路径），则**优先**使用该文件作为模板。  
2. **知识库优先检索 + MCP 补充（先于写 note）**：在落盘 `*_note.md` 之前，按顺序检索：  
   - `D:/Obsidian/repository/Obsidian Vault/**/*.md`（若存在且可读）；  
   - 否则/同时 **仓库内** `obsidian-vault/**/*.md`（尤其 `LLM_Learning/wiki/concepts/`、`topics/`、`entities/`）；  
   将命中文件路径与要点作为正文依据。若仍不足，再用 MCP/Web 拉取权威公开文档。  
   **禁止**无来源臆造术语定义。  
3. **笔记内显式「本地知识库命中」**：每个 `{子知识点}_note.md` 在 `<参考资料>` **之后**、`## 一、核心定义` **之前**，增加独立小节：  

```markdown
## 本地知识库命中（生成前检索）

- （相对仓库根的路径，如 `obsidian-vault/LLM_Learning/wiki/concepts/functions.md`）

```

无命中时写一行：`无与本节强相关的本地条目；以下依据外部文档归纳。`  

4. **模板内「参考资料」必填**：模板顶部的 **参考资料** 区块须含 **可点击的 https URL**（官方文档优先）；**避免**把仅本机存在的 `file:///D:/...` 作为唯一引用。本地证据放在上一节的「本地知识库命中」列表中。  
5. **回复与 summary**：在聊天回复里用列表给出本次采用的 URL；每个生成的 `*_summary.md` 底部须有 **「参考文献（MCP）」** 小节，与 note 中参考资料及 chat 所列一致或为其合理子集；**summary** 须增加 **「本地知识库索引」** 小节，罗列本模块生成时检索过的 `obsidian-vault/` 条目（可无命中说明）。

### 目录与命名（必做）

在 `notebooks/` 下创建 **`【知识块】/`** 文件夹（例：`函数式/`），其内包含：

| 文件 / 目录 | 说明 |
|-------------|------|
| `【知识块】_summary.md` | **定义**（精准）、**通俗比喻**、**子知识点列表**、**知识图谱**（推荐 Mermaid）、学习顺序说明、闭环提示（note → practice → 费曼）、参考文献 |
| `NN_子知识点短名/` | `NN` 为**两位序数**学习顺序（`01_`…）；每子文件夹内必含：`{子知识点}_note.md`，以及**多个**按习题拆分的练习文件（见下） |

`note`：按**笔记模板**撰写的该点**全面通俗讲解** + 文内 **demo** 代码块（Markdown fenced code）；顶部 **参考资料** 已填 MCP URL。  

`practice`（强制拆分与命名）：  
- **禁止**仅用单个 `{子知识点}_practice.py` 堆砌全部习题；须按**独立练习意图 / 验收点**拆成多个 `.py` 文件。  
- **文件名**：`{知识点}{两位序号}_{练习要点}.py`  
  - `{知识点}`：与文件夹内 `{子知识点}_note.md` 的 `{子知识点}` **完全一致**（例：`lambda与闭包`）。  
  - `{两位序号}`：本文件夹内练习文件顺序，从 `01` 起递增（`01`、`02`、`03`…）。  
  - `{练习要点}`：简短中文或小写 snake_case，概括本题核心（例：`闭包延迟绑定`、`默认参数陷阱`），避免空格与非法路径字符。  
  - 示例：`lambda与闭包01_延迟绑定演示.py`、`lambda与闭包02_循环中闭包.py`。  
- 每个文件：**一道（或一组紧密相关的）实战习题** + 可运行 **自测**（`if __name__ == "__main__"` 内断言或打印验收）；**默认**提供可一键跑通的参考答案，文件首注释注明「练习时可先遮住实现自行编写」。  
- 可选：在同目录增加 `{子知识点}_practice_index.md` 用列表说明「文件名 ↔ 练习目标」，便于检索（非必须）。

知识块与**子知识点**划分须覆盖该块主干（粒度适中，忌单文件堆砌）。

### 费曼检验（必做）

当用户完成该子文件夹内**全部**拆分练习（或约定完成的子集）的自测后，引导其发送「精准指令 4」或通过话术进入**费曼检验**；代理以**小白身份**连续追问直至用户能把该点**讲清、无关键矛盾**。

### 与旧文件的关系

若 `notebooks/` 下曾存在单文件 `{知识块}_note.py`，可改为**跳转 stub** 指向新 `【知识块】/` 目录，避免重复维护两套长篇正文。

## 输出验证（闭环最后一步）

在每一阶段结束时，代理应推动**可检查产出**，例如：

- 小测验全对或错题已复述修正；
- 一段能运行的代码或通过的测试；
- 用户用话复述「地图」中的某一核心点且无关键错误。

验收写进子工程内 `README.md`（`skills/…` 或 `learning/…/…`）的「阶段验收」列表，便于下次续学。

## 约束

- 子工程创建须符合本仓库已有约定：每技能独立目录、`venv`、可编辑安装，见仓库根目录 `README.md`。  
- 不要覆盖用户已有 `skills/*` 与 `learning/*` 目录中的内容；重名时先询问。  
- 文件路径在 Skill 与回复中使用正斜杠（如 `skills/_template`）。
